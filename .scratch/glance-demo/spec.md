# Glance livestock geofence demo

## Goal and boundaries

Replace the Expo starter with an iOS and Android demo that stores a single active geofence, up to five manually added demo devices, their simulated positions, and recent breach history in local SQLite through Drizzle. Web is not a demo target; if its tab shell is kept aligned, its Map route remains a simple placeholder and does not import MapLibre. There is no account, server sync, GPS tracking, physical tracker, buzzer hardware, or notification delivery. The buzzer is a visual-only control/state. Use NativeWind for the interface and the already installed `react-native-vector-icons` for icons; do not use emoji or add Expo Symbols for this work.

Use MapLibre with the OSM-based OpenFreeMap Liberty style (`https://tiles.openfreemap.org/styles/liberty`) and keep its attribution, including © OpenStreetMap contributors, visible. Map tiles need a network connection; device, geofence, position, and violation data remain local. No GPS permission is needed.

## User flow

1. **Map opens first.** The root route is the Map tab. Show the saved polygon, device markers, selected device details (ID and current coordinates), visual buzzer control, and a small newest-first violation list. Support map pan and pinch zoom, plus visible zoom-in/zoom-out controls. Fit the camera to the saved polygon and device positions with padding. With no saved polygon, provide a clear path to Setup.
2. **Setup creates demo data.** Present a geofence drawer over the map for drawing or replacing the polygon, with save/cancel controls; tapping the map adds ordered vertices. Require at least three distinct, in-range vertices, non-zero area, and a valid non-self-intersecting ring. Close the ring for display automatically. Replacing a saved polygon requires explicit confirmation in a clearly labeled UI prompt: confirmation saves the new polygon, retains device IDs and violation history, clears simulated positions, and marks any active violation as `fence_changed` with a resolution timestamp. It must not label that incident `Returned`. Canceling replacement or submitting an invalid polygon preserves the prior polygon, positions, and violation records/statuses. Allow the user to add and remove devices by ID, with no more than five and no duplicate or blank IDs.
3. **Simulate locations on Map.** Show floating action buttons with labeled icons from the existing `react-native-vector-icons`: “Place herd inside” assigns every configured device a deterministic point inside the active polygon; for the selected device, “Simulate breach” moves it outside and “Simulate return” moves it inside. All actions use the same persisted position update and geofence evaluation path; no separate shortcut creates violation rows. The outside/return actions are unavailable until a polygon and device exist.
4. **Inspect state and alerts.** Tapping a marker selects it and shows its ID and current coordinates. On breach or return, show an in-app visual alert with device ID, `Outside` or `Returned` status, event coordinates, and the exact detection timestamp (not relative text such as “just now”). Recent history distinguishes active `Outside`, `Returned`, and `Fence changed` incidents, retaining the original breach coordinates/time; returned incidents also retain return coordinates/time, and fence-changed incidents show their resolution time. The visual buzzer control changes an independent, clearly labeled visual state; it does not play audio or infer its state from whether the device is inside or outside. There is no OS notification delivery.

## State and behavior invariants

- There is at most one active geofence, and it is a valid polygon. Persist its ordered vertices and update time.
- There are at most five demo devices. Persist each ID and latest simulated latitude/longitude.
- Confirming a replacement polygon atomically retains device IDs and all violation rows, clears simulated positions, and marks any active violation `fence_changed` with `resolvedAt`; it must not be reported as `Returned`. Devices need “Place herd inside” before breach/return simulation resumes. Cancel or invalid replacement leaves the prior polygon, positions, and history unchanged.
- Persist one violation lifecycle row per breach, with device ID, outside coordinates and `outsideAt`, nullable return coordinates, nullable `resolution` (`returned` or `fence_changed`), and nullable `resolvedAt`. A device can have at most one active row (`resolution` is null). Repeated outside updates do not create duplicates; an inside update resolves the active row as `returned` once and stores return coordinates/time. Replacing the polygon resolves each active row as `fence_changed` without changing its original breach data. A later exit creates a new row. Update position and lifecycle in one transaction so the alert/list cannot disagree with the marker.
- Saving the polygon alone does not invent a breach. “Place herd inside,” exit, and return all pass through the shared evaluator. Validate candidate inside/outside points before persisting them.
- Show the newest ten lifecycle rows. Display `Outside` when `resolution` is null, `Returned` when it is `returned`, and `Fence changed` when it is `fence_changed`; retain original breach data and the applicable return or resolution time.

## Implementation milestones

1. **Replace the starter shell.** Reuse `src/app/index.tsx` for Map and `src/app/explore.tsx` for Setup, keeping the current route files and the root as default. Align native iOS/Android tabs and, if retained, keep web tab labels with a Map placeholder. Keep the native MapLibre screen out of the web bundle. Put reusable UI and simulation logic outside `src/app/`.
   - Include the starter and lint-tooling cleanup needed for the final lint and typecheck gates to pass.
   - Acceptance: iOS and Android tab bars show only Map and Setup; launching the root route opens Map. Web mapping is out of scope.
2. **Add local schema and Setup flow.** Extend `db/schema.ts` for the geofence, demo devices, and violation lifecycle; add and apply Drizzle migrations at startup before querying. Build polygon validation and the device form. Keep writes behind a small local data-access layer around `src/utils/db.ts`.
   - Acceptance: a cold start applies migrations; Setup saves and reloads one valid polygon and 1–5 unique IDs; invalid geometry, duplicate IDs, and a sixth device are rejected without replacing saved data. Canceling a replacement preserves polygon, positions, and history; confirming it preserves IDs and history, clears positions, and marks active incidents `fence_changed` atomically.
3. **Add the map and simulation.** Isolate the MapLibre view in a reusable component. Render the polygon and device markers, fit the camera, and show attribution. Implement deterministic simulated positions and the single position/evaluation transaction; connect selection, exit, return, detail, visual buzzer, and recent history.
   - Acceptance: pan, pinch zoom, and zoom buttons adjust the map view. Floating actions have accessible labels and perform the named inside/breach/return updates. After “Place herd inside,” every marker is inside the displayed polygon and the camera includes all markers and the boundary; selected exit creates exactly one in-app alert and `Outside` row with coordinates and exact time; repeated outside updates create none; return updates the alert/row to `Returned` with return coordinates and exact time; replacing the polygon marks an active row `Fence changed` with a resolution time and preserves its breach data; a later exit creates a new lifecycle row. Buzzer toggling does not change geofence state.

## Verification

Baseline before implementation: `npx tsc --noEmit` fails because `src/components/animated-icon.web.tsx` has no CSS module declaration and `src/constants/theme.ts` has an undeclared side-effect import of `src/global.css`. The first `npx expo lint` run auto-installed ESLint because the repo has no lint config; those package/config changes were reverted. The subsequent lint run reported `setState` in an effect in `src/hooks/use-color-scheme.web.ts`. Treat these as existing starter/tooling baseline issues and resolve them within the starter-shell milestone. Then run `npx expo lint` and `npx tsc --noEmit`. No test runner is currently configured, so do not add a test framework for this demo; verify polygon validation and the repeated outside, return, and later exit transitions in the app flow. On a MapLibre development build, check the two-tab flow, geofence drawer, pan/zoom gestures and buttons, polygon save/reload, camera fit and attribution, labeled floating actions, placement inside, breach/return alert fields, and persistence after restart. Before interactive emulator/device QA, confirm the shared device is available.
